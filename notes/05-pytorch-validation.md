Занятие завершает блок линейных моделей: сначала смотрим, как обучить их средствами PyTorch и почему простой градиентный спуск может сломаться, затем разбираем валидацию и смысл метрик. Конспект объединяет обе части записи; материал первой части изложен по демонстрации ноутбука, второй — по объяснениям и вопросам после перерыва.

## 1. NumPy, тензоры и булева индексация

Тензор в PyTorch в этом занятии — многомерный массив чисел: скаляр имеет ноль осей, вектор одну, матрица две. Это вычислительный объект с формой, типом данных и устройством хранения; здесь не требуется отдельное определение тензора из алгебры.

Как и в NumPy, можно перемножать матрицы, суммировать по осям и выбирать элементы по булевой маске. В демонстрации для массива `0, 1, 2, 3, 4`:

```python
import numpy as np

a = np.arange(5)
mask = a % 2 == 0
print(a[mask])  # [0 2 4]
```

Сам массив остатков `a % 2` ещё не является булевой маской. Сравнение с нулём задаёт условие, а `a[mask]` оставляет элементы, для которых оно истинно. Это удобно для выбора объектов с заданным свойством.

Далее в лекции рисуется параметрический узор из синуса и косинуса. Он показывает, что знакомые численные операции есть и в PyTorch; смысл перехода к новому инструменту — прежде всего автоматические градиенты.

## 2. Граф вычислений и правило цепочки

Начнём с регрессии по одному признаку:

$$
\hat y=wx+b,\qquad \ell=(\hat y-y)^2.
$$

Граф содержит умножение, сложение, вычитание и квадрат. Значение потери получается прямым проходом, а производные по параметрам — применением правила цепочки в обратном направлении:

$$
\frac{\partial\ell}{\partial\hat y}=2(\hat y-y),\qquad
\frac{\partial\hat y}{\partial w}=x,\qquad
\frac{\partial\hat y}{\partial b}=1.
$$

Следовательно,

$$
\frac{\partial\ell}{\partial w}=2(\hat y-y)x,\qquad
\frac{\partial\ell}{\partial b}=2(\hat y-y).
$$

Входы $x,y$ в обычном обучении считаем данными, а $w,b$ — изменяемыми параметрами. Поэтому требуем градиенты для параметров. В других задачах можно дифференцировать и по входу; запрет здесь связан с постановкой, а не с возможностями библиотеки.

## 3. `requires_grad`, `backward` и накопление

Тензоры-параметры помечаются `requires_grad=True`. Операции над ними формируют граф; `loss.backward()` вычисляет производные, а `.grad` у листовых параметров содержит накопленный результат.

```python
import torch

x = torch.tensor([1., 2., 3.])
y = torch.tensor([2., 3., 4.])
w = torch.tensor(0., requires_grad=True)
b = torch.tensor(0., requires_grad=True)
loss = ((w * x + b - y) ** 2).mean()
loss.backward()
print(w.grad, b.grad)
```

На этом маленьком проверяемом примере градиент по $w$ равен $-40/3$, по $b$ — $-6$. Код иллюстрирует правило цепочки для средней потери, а не воспроизводит все данные демонстрации.

Градиенты **добавляются**, а не автоматически заменяются. Это позволяет собрать производную суммы нескольких потерь или нескольких батчей. Но если нужен один новый шаг по одному батчу, прошлые градиенты надо очистить. Типичный порядок:

```python
optimizer.zero_grad()
logits = model(x_batch)
loss = loss_function(logits, y_batch)
loss.backward()
optimizer.step()
```

Повторный `backward()` на том же уже освобождённом графе — отдельная проблема; накопление демонстрируют с заново вычисленным графом. Не нужно сохранять граф без необходимости. Для своих операций можно определить прямое вычисление и соответствующее правило обратного прохода; это не делает недифференцируемую операцию автоматически корректно дифференцируемой.

## 4. Почему регрессия разошлась

В демонстрации даже два параметра — наклон и свободный член — не защитили от расходимости. При большом масштабе $x$ градиент по весу содержит этот множитель. Слишком большой шаг сильно меняет предсказание, увеличивает ошибку и порождает ещё больший следующий шаг.

Для выборки из $m$ объектов:

$$
Q(w,b)=\frac1m\sum_{i=1}^{m}(wx_i+b-y_i)^2,\qquad
\frac{\partial Q}{\partial w}=\frac2m\sum_{i=1}^{m}(wx_i+b-y_i)x_i.
$$

Уменьшение learning rate может восстановить устойчивость, но сделать движение по другим направлениям очень медленным. После стандартизации данных демонстрация сходится заметно лучше:

$$
x_i'=\frac{x_i-\mu_{\rm train}}{s_{\rm train}}.
$$

Знаменатель здесь — **стандартное отклонение**, а не дисперсия. Среднее и масштаб оцениваются на обучающих данных. Масштабирование меняет геометрию оптимизации; универсального правила, что любые данные всегда следует нормировать одинаково, нет.

Вопрос о gradient clipping привёл к демонстрации ограничения значений. Поэлементная обрезка и ограничение нормы градиента — разные операции. Клиппинг может ограничить шаг, но не заменяет осмысленный learning rate, масштабирование и диагностику чисел. В записи произвольно выбранные границы не решили проблему автоматически.

## 5. Линейная модель для изображений букв

Изображение $28\times28$ разворачиваем в вектор из $784$ признаков. Для двух взаимоисключающих классов достаточно одного score:

$$
s=\mathbf w^{\mathsf T}\mathbf x+b,\qquad p=\sigma(s).
$$

`nn.Linear(784, 1)` хранит веса и свободный член, а сигмоида переводит score в вероятность. У начальной модели случайные параметры; её первые ответы ещё не являются обученным распознаванием.

Нулевое начальное значение может работать для простой логистической регрессии. Для скрытых нейронов с одинаковыми ролями оно создаёт проблему симметрии: они могут получать одинаковые обновления и оставаться одинаковыми. Поэтому вывод «никогда нельзя начинать с нуля» слишком широк; важно понимать архитектуру. Подробное объяснение инициализации нейросетей в лекции оставлено на дальнейшие занятия.

Смысл мини-батча: на одном шаге считаем потерю и градиент по небольшой случайной подвыборке, в записи используется размер $256$. Это позволяет многократно обновлять модель без полного прохода по всем объектам на каждом шаге.

## 6. Форма, тип и контракт функции потерь

В живом коде возникали ошибки с формами, типами и значениями. Полезно отдельно проверять:

- сколько объектов в батче и сколько ответов возвращает модель;
- что вход и целевая переменная соответствуют друг другу;
- где функция ждёт логиты, а где уже вероятности;
- что потери и параметры конечны и градиенты очищаются;
- что данные для обучения и оценки обрабатываются одинаково.

Для бинарной задачи можно использовать вероятность и `BCELoss` либо логит и `BCEWithLogitsLoss`. Не подаём сигмоиду второй раз в потерю, которая уже ожидает логиты.

Для $C$ взаимоисключающих классов нужен score каждого класса:

$$
\mathbf s=\mathbf W\mathbf x+\mathbf b,\qquad
\mathbf W\in\mathbb R^{C\times784},\qquad
p_c=\frac{e^{s_c}}{\sum_{r=1}^{C}e^{s_r}}.
$$

При обычных индексных метках `CrossEntropyLoss` получает логиты формы `(batch, C)` и целевые индексы формы `(batch,)` типа `torch.long`. Внутри уже есть эквивалент `log_softmax` и отрицательного логарифмического правдоподобия; отдельный softmax перед этой потерей не нужен. Существуют и другие поддерживаемые виды целей, но в демонстрации разбирались индексы классов.

Для многоклассового ответа выбирают `argmax` по оси классов. Порог первого столбца, подходивший для бинарной вероятности, не является корректной заменой этого правила.

## 7. Регуляризация и интерпретация весов

Автодифференцирование позволяет добавить штраф к той же цели:

$$
Q_{\rm reg}=Q+\lambda\sum_jw_j^2.
$$

Важно считать штраф от самого тензора параметров, сохраняя граф, а не от отделённых `.data` или NumPy-чисел. Обычно отдельно решают, штрафовать ли свободный член. Выбор $\lambda$ требует валидации.

В лекции вектор весов разворачивается обратно в изображение. Так можно увидеть, какие пиксели увеличивают или уменьшают score. В бинарном случае один вектор одновременно предпочитает один класс другому; в многоклассовом случае есть отдельная строка весов для каждого класса.

«Шаблон» — полезная зрительная интерпретация, но обученные веса не обязаны быть арифметическим средним картинок. Они отражают различение классов и зависят от других весов, данных и штрафа. Модель видит яркости в фиксированных координатах; инвариантность к переносу изображения сама собой не появляется.

## 8. После перерыва: качество на новых данных

Train нужен для настройки параметров, validation — для выбора модели и гиперпараметров, test — для финальной оценки выбранного решения. Названия можно менять, но роли должны оставаться разделёнными.

Сравнивать несколько моделей лучше на одинаковом разбиении: иначе разница качества может объясняться разной сложностью отложенных объектов. Нет универсальной обязательной пропорции вроде $60/20/20$. Объём проверки зависит от количества данных, редких случаев и требуемой точности оценки.

Падение train-потери при ухудшении validation — сигнал переобучения. Одна кривая не даёт универсальной гарантии, что дальше улучшения невозможны: в записи упоминался grokking как отдельный феномен, без подробного разбора. Практическое решение об остановке всё равно принимают по выбранному протоколу.

Чем больше вариантов попробовали на validation, тем больше информации о ней попало в выбор решения. Поэтому хорошая validation-метрика ещё не заменяет test. Если результат test использовали для дальнейших исправлений, этот набор уже не является нетронутой финальной проверкой.

## 9. Кросс-валидация и стратификация

В $K$-fold CV данные делят на $K$ непересекающихся частей. Каждый фолд по очереди становится валидационным, модель обучается заново на остальных:

$$
\overline{q}_{\rm CV}=\frac1K\sum_{j=1}^{K}q_j.
$$

Например, для пяти фолдов выполняем пять обучений на четырёх пятых данных. Получаем пять оценок и можем видеть их разброс. Это снижает зависимость от одного разбиения, но стоит дополнительных вычислений и не исправляет утечку автоматически.

**Уточнение применения:** все обучаемые преобразования, включая стандартизацию и PCA, оценивают внутри обучающей части каждого фолда. Для групп связанных объектов и для времени нужны соответствующие способы разбиения; случайное перемешивание не всегда соответствует будущему использованию модели.

При дисбалансе классов стратификация помогает сохранить их доли в фолдах. Она не делает классы равными по численности и не заменяет подходящую метрику. После выбора гиперпараметров можно переобучить итоговую модель на доступных обучающих данных; нетронутый test в этот набор не включается.

Усреднение нескольких моделей и одно обучение на объединённых данных не обязаны давать одинаковый результат, даже для линейных методов. Это разные варианты итогового решения.

## 10. Метрики регрессии: MSE, MAE и R²

Пусть теперь $m$ — число объектов **оцениваемой** выборки. Две базовые ошибки:

$$
\operatorname{MSE}=\frac1m\sum_i(y_i-\hat y_i)^2,\qquad
\operatorname{MAE}=\frac1m\sum_i|y_i-\hat y_i|.
$$

MSE сильнее выделяет большие ошибки и имеет квадрат единицы измерения ответа; MAE имеет исходную единицу. Одно число нельзя интерпретировать без масштаба задачи.

Коэффициент детерминации сравнивает ошибку модели с ошибкой предсказания среднего ответа той же оцениваемой выборки:

$$
R^2=1-\frac{\sum_i(y_i-\hat y_i)^2}{\sum_i(y_i-\bar y)^2},\qquad
\bar y=\frac1m\sum_i y_i.
$$

При ненулевом знаменателе: $R^2=1$ для безошибочного ответа, $R^2=0$ для результата с такой же суммой квадратов ошибок, как у среднего, отрицательное значение — хуже этой базы. Это сравнение, а не доля правильных ответов. Если все истинные ответы одинаковы, знаменатель нулевой: исходная формула не определена, библиотечное соглашение надо проверять отдельно.

**Небольшой расчёт для проверки:** $y=(1,2,3)$, $\hat y=(1,2,2)$ дают MSE $1/3$, MAE $1/3$, $R^2=1-1/2=0.5$.

MAPE и SMAPE в записи только упомянуты как способы относительной нормировки. Их формулы и соглашения здесь не выдаются за подробно разобранный материал; нормировка при нулевых или малых ответах требует осторожности.

## 11. Матрица ошибок и balanced accuracy

Для бинарной классификации фиксируем, какой класс положительный:

| Истинный класс | Предсказали положительный | Предсказали отрицательный |
| --- | --- | --- |
| Положительный | TP: верное обнаружение | FN: пропуск |
| Отрицательный | FP: ложное срабатывание | TN: верное отклонение |

`Positive/negative` называют предсказание, `true/false` — его правильность. Связь FP/FN с ошибками первого и второго рода зависит от того, какую нулевую гипотезу приняли; одной смены названий классов достаточно, чтобы запутать неоговорённую аналогию.

$$
\operatorname{Accuracy}=\frac{TP+TN}{TP+TN+FP+FN},\qquad
\operatorname{BalancedAccuracy}=\frac12\left(\frac{TP}{TP+FN}+\frac{TN}{TN+FP}\right).
$$

При соотношении классов $90/10$ постоянный ответ «большинство» даёт accuracy $0.9$, но balanced accuracy $0.5$: полнота большинства равна единице, меньшинства нулю. **Не $0.45$**: сначала считаем долю правильных внутри каждого класса, а не долю во всей выборке. Это уточнение численного примера из автоматической расшифровки.

## 12. Precision, recall и F-score

Для выбранного положительного класса:

$$
P=\operatorname{Precision}=\frac{TP}{TP+FP},\qquad
R=\operatorname{Recall}=\frac{TP}{TP+FN}.
$$

Precision отвечает, какая доля срабатываний верна; recall — какую долю настоящих положительных нашли. В формулах нет TN: показатели смотрят на задачу через выбранный класс. При нулевом знаменателе нужно явно выбранное соглашение, а не молчаливое деление.

Для $TP=8$, $FP=2$, $FN=4$ получаем $P=0.8$, $R=2/3$. Сами по себе высокие числа для класса большинства могут скрывать полный провал на меньшинстве. Поэтому смотрят результаты нужных классов отдельно и указывают способ усреднения.

Не следует делать более сильный вывод, что все показатели одинаково зависят от частоты класса: precision при фиксированных условных ошибках зависит от доли положительных, recall определяется условно внутри положительного класса. При изменении распределения объектов измениться могут оба.

Гармоническое среднее для одного выбранного класса:

$$
F_1=\frac{2PR}{P+R}=\frac{2TP}{2TP+FP+FN}.
$$

Для примера выше $F_1=16/22\approx0.727$. Малое значение одного аргумента ограничивает итог. Обобщение:

$$
F_\beta=\frac{(1+\beta^2)PR}{\beta^2P+R},\qquad \beta>0.
$$

Большая $\beta$ усиливает роль recall, малая — precision. При положительных аргументах пределы равны соответственно recall и precision.

**Дополнение по слайдам:** macro-F1 — арифметическое среднее F1 классов, weighted-F1 учитывает их численность, micro-F1 сначала суммирует счётчики. Гармоническое среднее F1 двух классов тоже можно определить, но это не стандартное определение macro-F1. Всегда указываем, что именно усреднили.

## 13. ROC: одна точка для порога, кривая для всех порогов

Для порога $t$ предсказываем положительный класс, если score не меньше $t$. Меняем порог — меняются TP, FP, FN и TN. ROC строится в осях:

$$
\operatorname{TPR}=\frac{TP}{TP+FN},\qquad
\operatorname{FPR}=\frac{FP}{FP+TN}.
$$

TPR — доля обнаруженных среди положительных, FPR — доля ошибочных срабатываний среди отрицательных. Это **условные доли в разных классах**, а не вероятность того, что конкретное предсказание правильно или неправильно.

Порог выше всех scores даёт $(0,0)$, ниже всех — $(1,1)$. Хорошее ранжирование позволяет сначала находить положительные с небольшим ростом FPR, поэтому кривая идёт ближе к левому верхнему углу. Конкретные равные scores создают скачки. Если доступны лишь готовые метки, а не изменяемый score, имеем одну рабочую точку.

Диагональ служит ориентиром случайного ранжирования; отдельно взятая точка ниже неё не доказывает, что все метки нужно перевернуть. Проверяем полную картину и смысл score.

**Дополнение по подготовленным слайдам:** ROC-AUC оценивает ранжирование:

$$
\operatorname{AUC}=P(s_+>s_-)+\frac12P(s_+=s_-).
$$

Здесь случайно выбираются один положительный и один отрицательный объект. AUC не выбирает рабочий порог и не проверяет калибровку вероятностей. PR-кривая показывает precision и recall при разных порогах; её подробный разбор в записи оставлен для практики. То же относится к дальнейшим деталям AUC и калибровки: не подменяем обзор законченной темой.

- Предобработка обучена только там, где разрешено протоколом.
- Модель и гиперпараметры сравниваются на сопоставимых разбиениях.
